# 實作藍圖與自動化執行手冊

> 本文件是 ERP 轉型「**實作階段**」的單一事實來源（source of truth）。
> 任何一個工作階段（含自動化迴圈）都應：**讀本檔 → 找到第一個未完成且相依已滿足的任務 → 執行 → 更新狀態 → commit/push**。

---

## A. 自動化運作方式（How automation works）

### A.1 環境工具鏈現況（2026-06，已實測）
| 工具 | 狀態 | 影響 |
| --- | --- | --- |
| Node 22 / npm 10 | ✅ 可用，npm registry 在允許清單 | **前端可在本機完整 build/test/lint** |
| api.nuget.org | ✅ 允許 | 後端 NuGet 還原可行 |
| github.com | ✅ 允許 | git 推送、CI 觸發、CI 結果讀取可行 |
| **.NET SDK 安裝來源** (`builds.dotnet.microsoft.com`) | ❌ **不在允許清單** | **後端無法在本機編譯** |

### A.2 兩條驗證路線（擇一或並用）
- **路線 1（預設）— CI 驗證後端**：後端程式碼以 GitHub Actions（runner 內建 .NET 8）建置與測試。流程：寫碼 → push → 讀 CI 結果（`mcp__github__actions_*`）→ 失敗則依 log 修正 → 綠燈才算完成。前端可同時在本機先驗證再 push。
- **路線 2（更快）— 開放允許清單後本機建置**：請在環境的網路 egress 設定加入下列主機，之後即可在本機 `dotnet build/test`，迴圈更快：
  - `builds.dotnet.microsoft.com`（SDK 安裝）
  - `dotnetcli.azureedge.net`、`dotnetcli.blob.core.windows.net`（部分套件/工作負載）
  - （NuGet 已開放）
  - 設定方式見 https://code.claude.com/docs/en/claude-code-on-the-web

### A.3 「完成」的定義（Definition of Done）
一個任務完成必須：① 程式碼/設定就位；② **CI 綠燈**（後端編譯 + 測試、前端 build + lint 通過）；③ 本檔狀態更新為 ✅；④ 已 commit 並 push 到 `claude/gallant-bohr-druvi6`。

### A.4 連續自動化（hands-off）的方法
- **逐任務推進**：每個工作階段做完一批任務即 push，並更新本檔勾選狀態，下個階段接續。
- **`/loop` 定時推進**（可選）：設定一個定時迴圈，每次讀本檔執行下一個未完成任務（例：`/loop 30m 依 docs/05 執行下一個未完成任務並更新狀態`）。**屬自動、會耗用額度，需你明確同意才開啟。**
- **PR + 監看 CI 自動修**（可選）：以階段為單位開 PR，訂閱 PR 事件，CI 失敗自動修到綠燈。

### A.5 狀態圖例
`⬜ 未開始`　`🟦 進行中`　`✅ 完成`　`🚧 受阻（註明原因）`
